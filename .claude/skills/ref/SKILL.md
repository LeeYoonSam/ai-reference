# /ref

라이브러리 루트는 `/Users/leeyoonsam/Documents/ai-reference` 다. 아래 경로는 모두 이 루트 기준 절대 경로로 쓴다. 이 skill 은 다른 저장소에서도 불릴 수 있기 때문이다.

## 공통 준비

1. `/Users/leeyoonsam/Documents/ai-reference/index.md` 를 Read 한다.
2. index.md 가 없으면, 사용자에게 "라이브러리가 비어 있다" 고 알리고 멈춘다.
3. index.md 에 `- [` 로 시작하는 카드 줄이 없으면, 사용자에게 "라이브러리가 비어 있다" 고 알리고 멈춘다.
4. `date +%F` 로 오늘 날짜를 얻는다.
5. $ARGUMENTS 가 비어 있으면, 사용자에게 찾을 말을 묻고 멈춘다.

## 모드 선택

1. $ARGUMENTS 가 "추천" 으로 시작하면, 추천 모드를 쓴다.
2. 그 밖의 경우에는 찾기 모드를 쓴다.

## 찾기 모드

1. index.md 의 카드 줄에서 $ARGUMENTS 와 맞는 카드를 최대 5장 고른다.
2. 맞는 카드가 없으면, 사용자에게 "맞는 카드가 없다" 고 알리고 멈춘다.
3. 고른 카드마다 frontmatter 의 `source_url` 줄을 `grep -m1 '^source_url:'` 로 읽는다.
4. 카드마다 제목, 한 줄 요약, 원문 링크, review_by 를 보여 준다.
5. review_by 가 오늘보다 이전이면, 그 카드에 "재검증 필요" 를 붙인다.
6. 카드 본문은 사용자가 요청할 때만 Read 해서 보여 준다. 찾기 결과의 독자는 사람이므로 목록만으로 충분하다.

## 추천 모드

1. "추천" 뒤의 문장을 작업 설명으로 쓴다.
2. 찾기 모드 1단계와 3~5단계를 한다.
3. 맞는 카드가 없으면, 사용자에게 알린다. 그리고 6단계, 11단계, 12단계, 14단계만 한다.
4. 고른 카드의 본문을 Read 한다.
5. `status` 가 `deprecated` 인 카드는 추천에 쓰지 않는다. 폐기된 조언이 작업 모델에게 전달되기 때문이다.
6. 작업 설명에 목표나 데이터 위치가 없으면, 사용자에게 한 번에 1개씩 묻는다. 질문은 3개 이하로 한다.
7. 추천 프롬프트 1개를 쓴다. 프롬프트에는 목표, 이유, 원천 데이터 위치, 검증 방법만 넣는다.
8. 추천 프롬프트에 역할 문장을 넣지 않는다. 역할 문장은 모델의 활용 범위를 좁힌다.
9. 추천 프롬프트에 카드 원문을 붙이지 않는다. 낡은 지시가 새 모델의 판단을 방해하기 때문이다.
10. 카드의 원칙을 작업에 맞는 문장으로 바꿔 쓴다.
11. 카드를 쓰지 않은 기본 프롬프트 1개를 쓴다.
12. 두 프롬프트를 각각 ```` ```text ```` 코드 블록 1개에 넣는다.
13. 적용한 카드 id 를 나열한다. "재검증 필요" 카드는 표시를 붙인다.
14. 사용자에게 두 프롬프트를 각각 새 세션에서 실행하라고 안내한다.
15. 사용자에게 비교 결과를 `/Users/leeyoonsam/Documents/ai-reference/log.md` 에 1줄로 남기라고 안내한다. 예: `2026-11-02 compare | grade-outside-session | 추천 승`
